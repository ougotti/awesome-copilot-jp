# シナリオ別ユースケース集

> **対象ツール**: ツール非依存 ｜ **実行環境**: Chat UI（「エンジニア」節のみ IDE / CLI） ｜ **対象読者**: 全職種（非エンジニア含む） ｜ **最終更新**: 2026-08-01

> 「生成AIで結局なにができるの？」に答える、**業務シーン別の実例カタログ**です。役割・場面から探して、自分の仕事に近い使い方を見つけてください。

各シナリオには次の 4 点を添えています。**そのまま貼って使えるテンプレート**にしてあるので、`〈 〉` の部分を自分の状況に置き換えてください。

| 項目 | 意味 |
|------|------|
| **用意するもの** | 添付するファイルや、事前に決めておく情報 |
| **頼みかた** | 入力・制約・出力形式を含む再利用可能なテンプレート |
| **受け取るもの** | 期待できる出力の形式 |
| **確認する項目** | 提出前に人が必ず見るところ |

> 情報の取り扱い・出力確認の共通ルールは **[生成AIを業務で安全に使う](safety.md)** にまとめています。各シナリオでは繰り返しません。

## 総務・庶務

### 議事録を整える

- **用意するもの**: 会議の走り書きメモ（テキスト or 録音の文字起こし）、参加者名
- **頼みかた**:
  ```
  添付の会議メモを議事録に整えてください。
  - 出力形式: Word（.docx）
  - 構成: ①決定事項 ②ToDo（担当者・期日つきの表） ③次回までの宿題 ④保留・持ち越し事項
  - 制約: メモに書かれていない担当者や期日を推測して補わないこと。
    不明な箇所は「要確認」と明記してください。
  ```
- **受け取るもの**: 上記 4 セクション構成の Word ファイル
- **確認する項目**: 担当者・期日の割り当て、決定事項の取り違え、「要確認」箇所の埋め戻し
- **関連**: [事務・バックオフィス活用ガイド](office-work.md#-議事録文書作成)

### 社内案内文を量産する

- **用意するもの**: 案内文のテンプレート、宛先リスト（氏名・部署などを含む表）
- **頼みかた**:
  ```
  添付のテンプレートと宛先リストで、宛名差し込み済みの案内文を全員分作ってください。
  - 出力形式: Word（.docx）、1 名 1 ページ
  - 制約: テンプレートの文面は変更せず、差し込み箇所のみ置換すること
  ```
- **受け取るもの**: 宛名差し込み済みの Word ファイル
- **確認する項目**: 氏名・敬称・部署の表記、差し込み漏れ、人数の一致
- **関連**: [事務・バックオフィス活用ガイド](office-work.md#-議事録文書作成)

### 長い資料を要約する

- **用意するもの**: 対象の PDF / Word 資料
- **頼みかた**:
  ```
  添付資料を要約してください。
  - 出力形式: 箇条書き（要点 5 つ）＋ アクション項目
  - 制約: 各要点に、資料中の該当ページ番号を添えること。
    資料に書かれていない情報を補足しないこと。
  ```
- **受け取るもの**: ページ番号つきの要点リストとアクション項目
- **確認する項目**: 重要な条件・例外が落ちていないか、ページ番号の対応
- **関連**: [Anthropic 公式スキル（pdf）](../claude-code/official-skills.md)

## 経理・財務

### 請求書 PDF から情報を転記する

- **用意するもの**: 請求書 PDF（複数可）
- **頼みかた**:
  ```
  添付の請求書 PDF から、次の項目を表に抜き出してください。
  - 抽出項目: 請求日 / 取引先名 / 件名 / 税抜金額 / 消費税額 / 税込金額 / 支払期日
  - 出力形式: Excel（.xlsx）、1 請求書 1 行
  - 制約: 読み取れなかった項目は空欄にし、推測で埋めないこと。
    最後に「読み取れなかった項目」の一覧を付けてください。
  ```
- **受け取るもの**: 1 請求書 1 行の Excel と、未読取項目のリスト
- **確認する項目**: **金額と税額の検算**、取引先名の表記、支払期日、未読取項目の手当て
- **関連**: [事務・バックオフィス活用ガイド](office-work.md#-請求書帳票)

### 複数 Excel の集計を統合する

- **用意するもの**: 統合したい Excel ファイル（複数）、集計軸の指定
- **頼みかた**:
  ```
  添付の 3 つの経費表を 1 枚のシートに統合してください。
  - 集計軸: 月別 × 部門別
  - 出力形式: Excel（.xlsx）。集計シートと、統合前の明細シートを分けること
  - 制約: 元データの値は変更しないこと。
    表記ゆれ（部門名など）を統一した場合は、変換対応表を別シートに残すこと
  ```
- **受け取るもの**: 集計シート・明細シート・変換対応表を含む Excel
- **確認する項目**: 合計値が元ファイルの総和と一致するか、名寄せの妥当性、重複計上
- **関連**: [事務・バックオフィス活用ガイド](office-work.md#-表計算集計)

### 月次決算のドラフトを作る

- **用意するもの**: 当月・前月の試算表、大きく動いた勘定の背景情報
- **頼みかた**:
  ```
  添付の試算表から、前月比で大きく動いた勘定の差異説明コメント案を作ってください。
  - 対象: 変動額 100 万円以上、または変動率 20% 以上の勘定
  - 出力形式: 勘定科目 / 前月 / 当月 / 差異 / 差異率 / 説明案 の表
  - 制約: 説明案は「考えられる要因」として書き、断定しないこと
  ```
- **受け取るもの**: 差異一覧と説明案の表
- **確認する項目**: 差異額の再計算、説明の裏付け、**有資格者による最終確認**
- **関連**: [金融サービス向けスキル（Month-End Closer）](financial-services.md#エージェント一覧主なもの)

### 勘定照合（突合）する

- **用意するもの**: 台帳データ、銀行明細
- **頼みかた**:
  ```
  添付の台帳と銀行明細を突き合わせてください。
  - 出力形式: ①一致した取引 ②台帳のみ ③明細のみ ④金額差異あり の 4 シート
  - 制約: 突合のキー（日付・金額・摘要のどれを使ったか）を明記すること。
    原因は「候補」として挙げ、断定しないこと
  ```
- **受け取るもの**: 4 分類の突合結果と原因候補
- **確認する項目**: 突合キーの妥当性、未消込の残高、**有資格者による最終確認**
- **関連**: [金融サービス向けスキル（GL Reconciler）](financial-services.md#エージェント一覧主なもの)

## 営業・営業事務

### 提案資料をスライド化する

- **用意するもの**: 提案メモ、自社のスライドテンプレート（あれば）
- **頼みかた**:
  ```
  添付の提案メモをスライドにしてください。
  - 出力形式: PowerPoint（.pptx）、10 枚以内
  - 構成: 表紙 / 課題 / 解決策 / 導入効果 / 価格 / 導入ステップ / 次のアクション
  - 制約: 1 枚あたりの箇条書きは 5 行以内。
    メモにない数値や実績を追加しないこと
  ```
- **受け取るもの**: 指定構成の PowerPoint
- **確認する項目**: 価格・数値の正確さ、実績の裏付け、テンプレート体裁
- **関連**: [事務・バックオフィス活用ガイド](office-work.md#-プレゼン報告資料)

### 見積書・請求書のドラフトを作る

- **用意するもの**: 取引内容（品目・数量・単価）、自社の帳票フォーマット
- **頼みかた**:
  ```
  次の取引内容で見積書を作ってください。
  - 取引内容: 〈品目・数量・単価〉
  - 出力形式: Excel（.xlsx）、添付フォーマットに合わせる
  - 制約: 消費税は 10%。小計・消費税・合計を分けて表示し、端数処理は切り捨て。
    計算式をセルに残すこと（値の直接入力にしない）
  ```
- **受け取るもの**: 計算式入りの見積書 Excel
- **確認する項目**: **単価・数量・税額・合計の検算**、端数処理、有効期限や取引条件
- **関連**: [事務・バックオフィス活用ガイド](office-work.md#-請求書帳票)

### 問い合わせ対応メールを下書きする

- **用意するもの**: 受信したメールや問い合わせ内容、対応方針
- **頼みかた**:
  ```
  添付の問い合わせに返信する案を作ってください。
  - 対応方針: 〈返金する / 代替案を提示する など〉
  - 出力形式: 件名 + 本文のメール形式
  - トーン: 丁寧、お詫びを含む、200 〜 300 字
  - 制約: 確定していない補償内容や期日を書かないこと
  ```
- **受け取るもの**: 件名つきのメール下書き
- **確認する項目**: 約束していない内容が入っていないか、宛名・敬称、社内承認の要否
- **関連**: [事務・バックオフィス活用ガイド](office-work.md#-メール社内コミュニケーション)

## 人事・採用

### 募集要項・案内文を作る

- **用意するもの**: 職務内容のメモ、対象ポジションの条件
- **頼みかた**:
  ```
  次の職務内容から求人票のドラフトを作ってください。
  - 出力形式: Word（.docx）
  - 構成: 職務概要 / 具体的な業務 / 必須スキル / 歓迎スキル / 働き方 / 選考フロー
  - 制約: 年齢・性別・国籍など、法令上書けない条件を含めないこと。
    メモにない待遇や条件を推測して書かないこと
  ```
- **受け取るもの**: 構成済みの求人票ドラフト
- **確認する項目**: **法令上の表現（差別的条件の排除）**、待遇の正確さ、人事責任者の確認
- **関連**: [Anthropic 公式スキル（docx）](../claude-code/official-skills.md)

### 応募データを整理する

- **用意するもの**: 応募者リスト（Excel / CSV）
- **頼みかた**:
  ```
  添付の応募者リストを整理してください。
  - 処理: 会社名の表記統一（「株式会社」の位置・前後空白・全角半角）
  - 追加: 「選考ステータス」列（未着手 / 書類選考中 / 面接 / 見送り / 内定）
  - 出力形式: Excel（.xlsx）。変更前後の対応表を別シートに残すこと
  - 制約: 応募者の氏名・連絡先は変更しないこと
  ```
- **受け取るもの**: 整形済みリストと変換対応表
- **確認する項目**: 名寄せの誤り（別会社の統合）、個人情報の取り扱い、件数の一致
- **関連**: [事務・バックオフィス活用ガイド](office-work.md#-表計算集計)

## 企画・マーケティング

### 市場・競合のリサーチを整理する

- **用意するもの**: 対象の記事・レポート（複数）
- **頼みかた**:
  ```
  添付の記事 5 本から業界トレンドをまとめてください。
  - 出力形式: トレンド 3 つ。各トレンドに「根拠となる記述」と「出典（記事名）」を添える
  - 制約: 記事に書かれていない推測を混ぜないこと。
    記事間で矛盾する主張があれば、まとめずに両論として示すこと
  ```
- **受け取るもの**: 出典つきのトレンド 3 点と、矛盾点の指摘
- **確認する項目**: 出典と記述の対応、記事の発行時期、一次情報かどうか
- **関連**: [金融サービス向けスキル（Market Researcher）](financial-services.md#エージェント一覧主なもの)

### 報告スライドを自動生成する

- **用意するもの**: 施策結果のデータ（Excel / CSV）、報告の相手と目的
- **頼みかた**:
  ```
  添付の施策結果データから月次報告スライドを作ってください。
  - 報告先: 〈経営会議 / 部内定例 など〉
  - 出力形式: PowerPoint（.pptx）、5 枚以内。主要指標はグラフにする
  - 構成: サマリ / 主要指標の推移 / 良かった点 / 課題 / 次月アクション
  - 制約: データにない要因分析を断定的に書かないこと
  ```
- **受け取るもの**: グラフ入りの報告スライド
- **確認する項目**: グラフの軸・単位・期間、数値とデータの一致、要因説明の裏付け
- **関連**: [事務・バックオフィス活用ガイド](office-work.md#-プレゼン報告資料)

## エンジニア

> **この節だけ実行環境が異なります。** 以下は IDE（VS Code など）またはターミナル（CLI）での作業を前提とし、リポジトリへの設定ファイル配置やコマンド実行が必要です。Chat UI だけで使いたい方は、ここより上の節を参照してください。

### コーディング規約を自動適用する

- **用意するもの**: リポジトリへの書き込み権限、適用したい規約
- **やりかた**: `.github/instructions/` に Instructions ファイルを配置すると、該当ファイルの編集時に自動で規約が効きます
- **確認する項目**: 既存コードとの矛盾、`applyTo` のパターンが意図どおりか
- **関連**: [Instructions 一覧](../copilot/instructions.md)

### 専門家ペルソナとして相談する

- **用意するもの**: 対象のコード、相談したい観点
- **頼みかた**: 該当ドメインの Agent を選択したうえで、「このコンポーネントの再レンダリングを最適化して。変更理由も説明して」のように観点を指定します
- **確認する項目**: 提案の根拠、計測せずに「速くなる」と断定していないか
- **関連**: [Agents 一覧](../copilot/agents.md)

### 定型タスクを `/` コマンドで実行する

- **用意するもの**: `.github/prompts/` または `.claude/skills/` に置いたテンプレート
- **やりかた**: `/` から PR レビューやテスト生成などのテンプレートを呼び出します
- **確認する項目**: 生成されたテストが実際に失敗を検出できるか
- **関連**: [Prompts / Skills 一覧](../copilot/prompts.md) ／ [Claude Code のカスタマイズ機能](../claude-code/basics.md)

### 体系的なデバッグ・TDD を行う

- **用意するもの**: 再現手順、失敗するテスト
- **やりかた**: superpowers の systematic-debugging / TDD スキルで、仮説と検証の手順を構造化します
- **確認する項目**: 症状ではなく原因を直しているか、テストを緩めていないか
- **関連**: [superpowers](../dev-methods/superpowers.md)
